===== SHEET: Guideline =====
R1: Guideline to make and understand Unit Test Case |  |  | 
R2:  |  |  | 
R3: 1. Overview |  |  | 
R4:  - In the template, Unit test cases are based on functions. Each sheet presents test cases for one function. |  |  | 
R5:  - Cover: General information of the project and Unit Test cases |  |  | 
R6:  - FunctionList: The list of Classes and Functions in the document.  /      + To control that the number of Unit TC meets customer's requirement or the norm, user should fill value for   /      'Normal number of Test cases/KLOC'.  |  |  | 
R7:      + Click on Function link to open the related Test cases of the function.   /      Note: You should create new Function sheet before creating the link |  |  | 
R8:  - Test Report: provive the overview results of Functions Unit test: Test coverage, Test successful coverage  /     (Summary, for normal/abnormal/boundary cases) |  |  | 
R9:      Note:  Should check the formula of "Sub Total" if you add more functions |  |  | 
R10:  |  |  | 
R11: 2. Content in Test function sheet |  |  | 
R12: 2.1 Combination of test cases. |  |  | 
R13:  - To verify that number of Unit TC meets customer's requirement or not. User has to fill number LOC of tested function and fill value of 'Normal number test cases/KLOC' item in FunctionList sheet, which is required by customer or normal value. The number of lacked TC is shown in 'Lack of test cases' item. |  |  | 
R14:  - If the number of Unit TC does not meet the requirement, creator should explain the reasons. |  |  | 
R15:  - If the number of  'Normal number test cases/KLOC' item in FunctionList sheet is not recorded, the number in 'Lack of test cases' is not calculated. |  |  | 
R16:  |  |  | 
R17:  2.2 Condition and confirmation of Test cases. |  |  | 
R18:  Each test case is the combination of condition and confirmation. |  |  | 
R19: a. Condition: |  |  | 
R20:         - Condition is combination of precondition and values of inputs. |  |  | 
R21:         - Precondition: it is setting condition that must exist before execution of the test case.  /                     Example: file A is precondition for the test case that needs to access file A. |  |  | 
R22:         - Values of inputs: it includes 3 types of values: normal, boundary and abnormal. |  |  | 
R23:                 . Normal values are values of inputs used mainly and usually to ensure the function works. |  |  | 
R24:                 . Boundary values are limited values that contain upper and lower values. |  |  | 
R25:                 . Abnormal values are non-expected values. And normally it processes exception cases.    |  |   |  
R26:         - For examples: |  |  | 
R27:             Input value belongs to 5<= input <=10. |  |  | 
R28:                . 6,7,8,9 are normal values. |  |  | 
R29:                . 5, 10 are boundary values. |  |  | 
R30:                . -1, 11,... are abnormal values.    |  |   | 
R31: b. Confirmation:  |  |  | 
R32:         - It is combination of expected result to check output of each function.  /           If the results are the same with confirmation, the test case is passed, other case it is failed.  |  |  | 
R33:         - Confirmation can include: |  |  | 
R34:                 + Output result of the function. |  |  | 
R35:                 + Output log messages in log file. |  |  | 
R36:                 + Output screen message... |  |  | 
R37: c. Type of test cases and result: |  |  | 
R38:         - Type of test case: It includes normal, boundary and abnormal test cases. User selects the type based on the type of input data. |  |  | 
R39:         - Test case result: the actual output results comparing with the Confirmation. /                  P for Passed and F for Failed cases. /           It can 'OK' or 'NG' (it depends on habit of the teams or customers) |  |  | 
R40:  |  |  | 
R41:  2.3. Other items: |  |  | 
R42:  - Function Code: it is ID of the function and updated automatically according to FunctionList sheet. |  |  | 
R43:  - Function Name: it is name  of the function and updated automatically according to FunctionList sheet. |  |  | 
R44:  - Created By: Name of creator. |  |  | 
R45:  - Executed By: Name of person who executes the unit test |  |  | 
R46:  - Lines of code: Number of Code line of the function. |  |  | 
R47:  - Test requirement: Brief description about requirements which are tested in this function, it is not mandatory. |  |  | 
R48:           |  |  | 
R49:  |  |  |
